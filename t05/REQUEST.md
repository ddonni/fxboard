# 과제 5 최종 실행 — 최초 요청 (AI A·AI B 공통)

이 문서와 `t05/CHECKS.md`, `t05/run_checks.js`는 **AI A가 시작하기 전에** 고정했습니다.
AI A와 AI B는 같은 요청·같은 검사·같은 상한으로 작업합니다. 이 폴더(`t05/`) 밖의
루트에 있는 `CHECKS.md`, `HANDOFF.md`, `T05_*.md`, `scripts/run_t05_checks.js`는 **이전
시도 기록**이며 이번 작업과 관계없습니다.

## 1. 요청 (완성할 기능 한 개)

> fx-board(오늘의 진짜 정보판)의 **"일별 기록" 표에 "전일 대비" 열을 추가**한다.
> 각 날짜 행에 바로 앞 날짜 대비 100엔당 원화 변화를 방향 기호·부호·소수 둘째 자리로
> 표시하고(예: `▲ +4.95`, `▼ -1.43`, `= 0.00`), 가장 이른 기록은 비교 대상이 없으므로
> `—`로 표시한다. 계산은 순수 함수 모듈 `daily-change.js`로 분리한다. 기존 화면과
> 기능(오늘 카드·스파크라인·정상값 증빙·일별 기록·CSV 다운로드·실제 이틀 대조·실패
> 재생·소개)은 깨지면 안 된다.

### 모듈 계약 (검사가 이 계약을 그대로 확인함)

- 파일: 저장소 루트의 `daily-change.js`. 외부 라이브러리 없이 순수 JS.
- Node에서는 `require("./daily-change.js").computeDailyChanges`, 브라우저에서는
  `window.DailyChange.computeDailyChanges`로 쓸 수 있어야 한다(UMD — 루트의
  `sparkline.js`와 같은 방식).
- `computeDailyChanges(rows)`
  - 입력: `[{ record_date: "YYYY-MM-DD", normalized_value: number, ... }]` —
    `data/history.json`의 `daily_readings` 행을 그대로 넣을 수 있어야 한다(이 두 필드는
    실제 데이터에 최상위로 존재함을 확인함).
  - 출력: `record_date` 오름차순으로 정렬한 **새 배열**. 입력 배열과 입력 객체는 바꾸지
    않는다. 각 원소는 `{ record_date, value, delta, direction, label }`.
  - `delta`: 앞 날짜 대비 차이. 소수 둘째 자리까지 정확해야 한다(예: 880.30 − 880.10 =
    정확히 `0.2`). 가장 이른 원소는 `null`.
  - `direction`: `"up"`(delta>0) / `"down"`(delta<0) / `"flat"`(delta=0) / `null`(첫 원소).
  - `label`: 기호 + 공백 + 부호 + 소수 둘째 자리.
    - 상승 `▲ +4.95` (▲ = U+25B2), 하락 `▼ -1.43` (▼ = U+25BC, 부호는 ASCII `-`),
      횡보 `= 0.00` (ASCII `=`), 첫 원소 `—` (U+2014 em dash 한 글자).
- 화면: "일별 기록" 표(`#history-table`)에 제목이 정확히 `전일 대비`인 `<th>` 열을 추가하고,
  각 행의 그 칸에 해당 날짜의 `label`을 그대로 표시한다. 기존 4개 열은 그대로 둔다.

## 2. 작업 분담 계획 (계획한 중단 지점)

- **AI A**: `daily-change.js`(순수 계산 모듈)까지만 구현하고 **멈춘다**. 화면(`index.html`,
  `app.js`, `style.css`)은 건드리지 않는다. 멈출 때 인수인계 문서를 남긴다.
- **AI B**: 저장소와 AI A의 인수인계 문서만 보고 화면 통합을 마쳐 검사 10개를 통과시킨다.

## 3. 공통 사용 상한 (AI A, AI B 각각 동일)

| 상한 | 값 | 측정 방법 |
|---|---|---|
| 시간 상한 | **세션당 20분** | 세션 시작~마지막 커밋 (학생 쪽 실행 기록 + 세션 자체 기록) |
| 요청·호출 수 상한 | **세션당 도구 호출 40회** (요청은 세션 시작 요청 1회) | 학생 쪽 실행 기록의 도구 호출 수 |

상한에 가까워지면 새 작업을 벌이지 말고, 그때까지의 상태를 저장하고 기록한 뒤 멈춘다.
외부 네트워크(패키지 설치 등)는 쓰지 않는다 — 필요한 도구는 이미 설치되어 있다.

## 4. 검사

`t05/CHECKS.md`의 고정 검사 10개(DC-01~DC-10). 실행: 저장소 루트에서
`node t05/run_checks.js`. 실행할 때마다 결과가 `t05/runs.jsonl`에 한 줄씩 자동으로
쌓인다(오류 회차 계산에 쓰임 — 지우거나 고치지 말고 커밋에 포함할 것).

## 5. 절차 규칙

### AI A

1. 시작하자마자 `date -u +%Y-%m-%dT%H:%M:%SZ` 결과를 `t05/SESSION_LOG.md`의 "AI A 시작"
   행에 적는다.
2. `daily-change.js`를 구현하고 `node t05/run_checks.js`로 확인한다(DC-01~06, DC-09~10이
   목표. DC-07·08은 화면 작업이라 AI B 몫).
3. **커밋 1 (작업 커밋)**: 코드 + `t05/runs.jsonl` + `t05/SESSION_LOG.md`.
4. `t05/HANDOFF.md`를 쓴다. **제목은 아래 7개를 이 순서·이 이름 그대로** 쓴다:
   `## 1. 목표` / `## 2. 현재 상태` / `## 3. 실행 명령` / `## 4. 통과 검사` /
   `## 5. 남은 문제` / `## 6. 다음 행동` / `## 7. 건드리지 말 것`
   - "현재 상태"에 커밋 1의 **전체 커밋 ID(40자)** 를 적는다.
   - "실행 명령"에는 처음 보는 사람이 **새 폴더**에서 따라 할 수 있게 필요 버전, 설치
     명령, 환경값 예시, 작업 폴더를 적는다.
   - "통과 검사"에는 마지막 실행의 10개 결과를, "남은 문제"에는 첫 실패 검사를 적는다.
5. `t05/SESSION_LOG.md`의 "AI A 종료·인계" 행에 시각·커밋 1 ID·자체 집계 사용량을 적는다.
6. **커밋 2 (인계 커밋)**: `t05/HANDOFF.md`와 `t05/SESSION_LOG.md`만 바꾼다. 그리고 멈춘다.

### AI B

1. 시작하자마자 시각과 `sha256sum t05/HANDOFF.md` 결과를 `t05/SESSION_LOG.md`의
   "AI B 시작" 행에 적는다(받은 인수인계가 AI A가 남긴 것과 같다는 증거).
2. 인수인계 문서만으로 막히는 곳이 있으면 `t05/SESSION_LOG.md`의 "인수인계 누락 기록"에
   **문서 누락**으로 적고 `t05/HANDOFF.md`를 고친다(수정 전 내용은 git 이력에 남는다).
   누락이 없으면 "없음"이라고 적는다.
3. 화면 통합을 마치고 `node t05/run_checks.js`로 10개를 확인한다.
4. "AI B 완료" 행에 시각·자체 집계 사용량을 적고 커밋한다(마지막 커밋이 B 완료 버전).

### 두 세션 공통 — 하지 말 것

- `t05/REQUEST.md`, `t05/CHECKS.md`, `t05/run_checks.js`를 바꾸지 않는다(검사 삭제·완화·
  기대값 변경 0건이어야 함).
- `t05/runs.jsonl`의 기존 줄을 지우거나 고치지 않는다.
- `data/` 아래 실제 데이터 파일을 바꾸지 않는다.
