# 과제 5 최종 실행 — 학생 쪽 감사 기록

두 세션(AI A, AI B)의 자체 보고와 별개로, 학생(진행 세션)이 저장소 상태·실행기·세션
실행 기록으로 독립 확인한 내용입니다. 대화 전문은 넣지 않았습니다. 사용량 원자료는
`t05/usage_measured.json`(세션 기록에서 기계적으로 집계: 요청 원문·도구 이름·명령 첫
줄·시각만), 새 폴더 재현 출력은 `t05/fresh_folder_repro.txt`입니다.

## 1. 고정 버전 (태그)

| 구간 | 시작 버전 | 종료 버전 |
|---|---|---|
| AI A | `t05f-a-start` = `75bb6e54e903ff794035048002d8986c6c277d7c` (기준선) | `t05f-a-end` = `926dd15a555e5343082243bdb9d75881184a0800` (인계 커밋) |
| AI B | `t05f-b-start` = `926dd15a555e5343082243bdb9d75881184a0800` | `t05f-b-end` = `f762e3b8449c58ff0dd4d7a7f544a13552ce4ca4` |

`t05f-a-work` = `e44baf13cbd2b8ca0deac732d27a2769ddaf5e42`은 인수인계 문서가 가리키는 AI A의
작업 커밋입니다. 재작업량(추가·삭제 줄 수)은 제출 뒤 채점기가 위 버전 쌍으로 계산하므로

## 3. 인수인계 (카드 3)

- **T05-C10 7칸**: `t05/HANDOFF.md`의 `##` 제목이 정확히 1. 목표 / 2. 현재 상태 / 3. 실행 명령 /
  4. 통과 검사 / 5. 남은 문제 / 6. 다음 행동 / 7. 건드리지 말 것 (스크립트로 대조, 일치).
- **T05-C11 새 폴더 재현**: 상속 환경변수가 없는 깨끗한 셸(`env -i`, PATH만 지정)에서 새
  폴더에 저장소를 clone하고 문서 3절 명령을 그대로 실행 → **8/10 PASS, 첫 실패 DC-07**.
  AI A가 문서 4·5절에 적은 결과와 같습니다(`t05/fresh_folder_repro.txt`).
- **T05-C12 버전 ID**: 문서의 `e44baf13…` = 실제 저장소의 커밋(종류 commit)이며 인계 커밋의
  부모와 정확히 같고, 두 커밋 사이 코드 차이(`t05/` 제외)는 0입니다.

## 6. 솔직하게 밝혀둘 점

- 두 세션은 같은 Claude 구독 안에서 서로 다른 모델로 띄운 새 세션입니다. 별도의 무료
  서비스를 연 것은 아닙니다.
- 검사를 고정하기 전에, 저장소 밖 임시 폴더의 참고 구현으로 10/10이 실제로 달성
  가능한지 확인했습니다(2차 시도의 검사 설계 결함을 반복하지 않으려는 목적). 참고 구현은
  어느 세션에도 주지 않았고 저장소에도 넣지 않았습니다.
- AI A는 시작 시각을 `Z` 없는 형식으로 적었습니다(값은 첫 호출 시각과 일치).
- 두 세션 모두 계획보다 훨씬 빨리 끝나서, 이번 비교는 "상한 안에서 끝났는가"는 분명히
  보여주지만 두 모델의 실력 차이를 가를 만큼의 표본은 아닙니다(각 1회, 맡은 절반도 다름).
